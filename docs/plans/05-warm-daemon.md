# v0.3 design: the warm action daemon

Implements the GO in [04-warm-daemon-spike.md](04-warm-daemon-spike.md). Numbers there: HID tap
375 ms → **1.1 ms**, AX tree 623 ms → **70 ms**, a mixed loop **2.7x** faster than pure
agent-device, taps landing 12/12. The cost is 22 transitive packages and a clean build that grows
from one minute to four — paid, this document argues, without charging it to `simprobe`.

## 1. Two products, one heavy

`simprobe` today has one dependency (`swift-argument-parser`) and builds in about a minute. Linking
grpc-swift into it would make `git clone && swift build` a twenty-minute proposition for someone who
only wants `wait-stable` — the repository's whole pitch. So the gRPC lives in a **second product**:

| Product | Target | Dependencies |
|---|---|---|
| `simprobe` | `simprobe` → `SimProbeCLI` → `SimProbeCore` | ArgumentParser |
| `simprobe-daemon` | `SimProbeDaemon` → `SimProbeCLI` | grpc-swift-2, -protobuf, -nio-transport |

The edge runs daemon → CLI, never the reverse: `SimProbeCLI` gains the *protocol* and the *client*,
both plain Foundation, and `swift build --product simprobe` never touches BoringSSL. `SimProbeDaemon`
reuses that library rather than getting one of its own, because everything it would put there — the
codec, the router, the element parser — is exactly what the client side needs too.

Generated stubs are vendored under `Sources/SimProbeDaemon/Generated/` (14 244 lines, idb protos
are MIT) with an origin header, regenerated by `scripts/regen-idb-stubs.sh` from **the installed
client's own descriptor**, not upstream `idb.proto`: upstream has grown fields the released
companion rejects. The script dumps `idb.grpc.idb_pb2.DESCRIPTOR` to a `FileDescriptorSet` and
feeds `protoc --descriptor_set_in`, so the stubs are wire-compatible by construction.

**Build-time budget**, measured here (8-core Apple Silicon, `.build` deleted first): `--product
simprobe` **58 s**; `swift build` **253 s** the first time and **115 s** after, since SwiftPM's
shared cache outlives `.build`; `-c release` **347 s**. The spike's ~19 minutes was a loaded box,
not the real cost. Four minutes fits a 10-minute CI budget, and `swift test` builds the whole graph
regardless — so **CI keeps one job and pays it** rather than splitting the daemon into a cached job
of its own. Binaries: 2.7 MB against 38.5 MB.

## 2. Wire protocol: newline-delimited JSON over a unix socket

`$TMPDIR/simprobe/<udid>.sock`, one line per request, one line per response.

```
-> {"op":"ping"}                    <- {"ok":true,"pid":41337,"udid":"...","uptimeMs":9214}
-> {"op":"tree"}                    <- {"ok":true,"ms":70.2,"treeJSON":"[{\"AXLabel\":…}]"}
-> {"op":"tap","x":201,"y":822}     <- {"ok":true,"ms":1.3}
-> {"op":"stop"}                    <- {"ok":true}
                                    <- {"ok":false,"kind":"idbFailed","message":"…"}
```

JSON and not protobuf so that `simprobe` needs no protobuf; a *string* field for the tree and not a
nested object so the payload round-trips through `Codable` untouched and is parsed in exactly one
place — `AccessibilityElementParser`, the same one `frames` uses. The gRPC `accessibility_info`
payload is the flat array `idb ui describe-all --json` emits, key for key.

`sun_path` is 104 bytes and `$TMPDIR/simprobe/<udid>.sock` measures 100 on macOS 26 — a four-byte
margin, so the resolver falls back to `/tmp/simprobe/<udid>.sock` above 103 rather than failing at
`bind()`. Directories are `0700`, the socket `0600`: it is an unauthenticated command channel.

## 3. Verbs

- `simprobe daemon start [--udid X] [--idle-timeout 10m]` — spawns `simprobe-daemon` detached
  (resolved as a sibling of `argv[0]`, which is how Homebrew installs them), waits for `ping`,
  then **smoke-tests**: tree ≥ 1 element **and** a `simctl` screenshot. Per the spike's caveat, idb
  screenshot breaks when the companion outlives a simulator reboot and reconnecting does not heal
  it, so capture stays on `simctl` everywhere and the smoke test proves the path a caller will
  actually use. Prints `daemon ready (<udid>, tree 16 elements, 45 ms)`.
- `simprobe daemon stop [--udid X]` — `{"op":"stop"}`, then `SIGTERM` by pidfile if the socket is
  gone, and only for a pid whose executable still matches what the daemon wrote down.
- `simprobe daemon status [--udid X] [--json]` — `running (<udid>, pid N, up 3m12s)` or
  `not running`, exit 0 either way: absence is a result, not an error.
- `simprobe tap <#id | @index | x,y> [--wait-stable]` — resolves a ref through the daemon's tree
  with the same parser `frames` uses, HID-taps the frame centre, prints
  `tapped #tabBar.list (201,822) 1.3 ms`. `--wait-stable` chains the existing `WaitStableRunner`,
  because a blind coordinate tap is swallowed by overlays on *both* engines.
- `simprobe tree [--interactive] [--json]` — `FramesRunner` over a daemon-backed
  `ElementDescribing`, so the output is `frames`' output, from the warm path.

**Node counts are not comparable across engines.** idb's tree is leaner by design: never diff
`simprobe tree` against `agent-device snapshot`, and never use either to assert *absence*.

Exit codes follow the existing table. A missing daemon is a new `ProbeError.daemonUnavailable`,
exit 2, carrying `simprobe daemon start --udid <udid>` — deliberately **not** an autostart, which
would hide a ~1.6 s cold start inside what the caller wrote as a tap.

## 4. The daemon

One process per UDID. Connects to `/tmp/idb/<udid>_companion.sock`, running `idb connect <udid>`
first when that socket is absent. Holds **one** `GRPCClient` for its whole life. Serves the socket
serially — a single simulator has one screen, and concurrent taps on it are a bug, not a feature.
Idle timer (default 10 min) exits the process; a pidfile beside the socket lets `stop` and
`status` find it; one JSON line per event to `$TMPDIR/simprobe/<udid>.log`.

If a call fails the daemon **reconnects once** (new channel, `idb connect` again) and retries —
the same connect-and-retry `IdbElementDescriber` already does, for the same reason: the first call
after a boot reliably fails with "No translation object returned". A second failure is reported to
the client as `idbFailed` and the daemon keeps serving rather than dying.

## 5. Testing

Everything above the gRPC line is unit-tested with fakes, and nothing in the test bundle links
grpc-swift:

| Suite | Covers | Fake |
|---|---|---|
| `DaemonProtocolTests` | codec round-trip, unknown op, truncated line, error envelope | — |
| `DaemonRoutingTests` | `op` → action dispatch, failure mapping | `FakeIdbActor` |
| `TapCommandTests` | `#id`/`@index`/`x,y` resolution, centre arithmetic, missing ref | `FakeDaemonClient` |
| `TreeCommandTests` | banded output, `--interactive`, `--json`, unreadable payload | `FakeDaemonClient` |
| `DaemonLifecycleTests` | spawn args, ping wait, smoke-test failure, stale pidfile, stop | `FakeProcessSpawner` |

The gRPC layer itself is only provable against a live simulator: `testLiveDaemonStartTapTreeStop`,
behind `SIMPROBE_LIVE=1` like the rest of `LiveSmokeTests`.

Coverage floor stays at 80 % over `Sources/`. `Generated/` never links into the `.xctest` bundle,
so it should not appear in the profile at all; if it does, `scripts/coverage-check.sh` grows one
commented exclusion for it — vendored generated code is not this repository's coverage to earn.

## 6. When to use which

`agent-device` stays the default: sessions, refs that survive relayout, `fill`, and the engine the
skill's ladder is written around. The daemon is for **loops** — observe, act, observe, dozens of
times — where 1.1 ms + 70 ms beats 1.0 s + 0.4 s, measured 2.7x faster end to end. Not a
replacement: no session, no `fill`, a leaner tree, a hard dependency on `idb_companion`.
